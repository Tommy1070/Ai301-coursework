# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Plan fidelity | The committed branch diff read against `plan.md`, including its stated scope, named files, implementation approach, and any `## Deviations` notes. | Pass if every material change in the diff is covered by the plan or an honestly recorded deviation, and the implementation does not silently add, omit, or contradict planned work. A disclosed shortfall may pass when the description and deviation notes accurately state it. | required |
| Test evidence proves the change | `test_evidence.md` read against the plan's test plan, the original reproduction, and the observable behavior of the changed code. | Pass if the evidence includes an observable before/after result for the reported problem and demonstrates whether the planned validation was actually performed. Honest reported failures or limitations do not fail this check solely because they are failures; hidden, missing, or unverifiable evidence does. | required |
| Repository checks are accounted for | The recorded results of repository checks named by the plan, PR package, or repository requirements, read against any stated limitations or unavailable checks. | Pass if applicable checks have observable outcomes, and any check that was not run, unavailable, or not applicable is explicitly and honestly disclosed. Fail when a required or claimed check is silently omitted, or when the PR claims success without supporting evidence. | required |
| Diff is reviewable and bounded | The branch diff's changed files and hunks read against the issue, plan boundary, and intended fix. | Pass if the diff contains only issue-relevant implementation and test changes, with no debug debris, commented-out experiments, unrelated cleanup, or other changes that unnecessarily bury the fix. | required |
| Description matches the diff | The draft PR title and description read against the committed branch diff and supporting evidence. | Pass if every material claim the description makes about the implementation and testing is supported by the diff or evidence. Do not fail solely because the description is concise or omits a non-required detail; omissions belong to the standards check when the repository explicitly requires that information. Fail when the description makes a materially false, contradicted, or unsupported claim about what changed or what was tested. | required |
| Repository standards and disclosure are satisfied | The draft PR description read against the repository's PR template, `docs/CONTRIBUTING.md`, issue-linking requirements, and stated AI-use disclosure expectations. | Pass if the draft addresses the repository's required template asks, identifies the issue, includes the required AI-use disclosure, and honestly records relevant deviations, omissions, or testing limitations. | required |

## Verdict rule

Accept only if every required check passes. Any failed or unclear required check causes a reject. Preferred checks, if any are added later, may provide guidance but never change the verdict. Treat `unclear` as fail because evidence that cannot be verified is not sufficient to declare the PR ready to submit. An honestly disclosed shortfall does not cause rejection by itself when the plan, description, diff, and evidence consistently disclose it and the repository's rules allow submission in that state.
